Последовательность команд и точки продолжения

В конце тела цикла переход возвращает исполнение к проверке условия. Проверка выбирает, продолжать ли цикл или перейти к команде после него. При разборе цикла начните с адреса проверки и проследите, где исполнение возвращается к ней и где выходит из цикла.

Вызов процедуры добавляет задачу сохранения места возврата. В разных архитектурах адрес возврата может сначала попасть в специальный регистр или сразу в стек. В примерах x86-64 проследим, как вложенные вызовы сохраняют разные адреса.

Как процессор выбирает следующую команду

При обычном последовательном выполнении следующая команда определяется положением текущей в коде. Команда перехода изменяет этот порядок. Безусловный переход выбирает новый адрес независимо от данных, условный — только при выполнении заданного условия. С помощью переходов реализуются ветвления, циклы и часть механизмов вызова. Процессор не хранит отдельного понятия «если» из языка высокого уровня: он выполняет сравнение и команды изменения управления.

В x86-64 сравнение обычно изменяет флаги состояния, не сохраняя результат вычитания как обычное число. Условный переход затем проверяет нужное сочетание флагов. Один набор битов можно интерпретировать как знаковое или беззнаковое число, поэтому сравнения для этих случаев различаются. Например, 11111111₂ означает 255 без знака и −1 в восьмиразрядном дополнительном коде. Сравнение с единицей даст разные отношения. Выбор перехода должен соответствовать типу сравниваемых данных, иначе программа будет правильно исполнять неверно заданное условие.

Условие перехода нужно читать вместе с предшествующим сравнением. Если сравнение относится к другим значениям или его флаги были изменены промежуточной командой, переход проверит не предполагаемое условие. Для пошаговой трассировки фиксируют операнды сравнения, полученное отношение и выбранный адрес. Такой способ полезен при изучении низкоуровневого кода и отладке.

В x86 команда CMP обновляет признаки так, как если бы выполнила вычитание, и оставляет операнды прежними. В синтаксисе AT&T из второго операнда вычитают первый. Флаг ZF показывает нулевой результат, CF — заём при беззнаковом вычитании, SF — знак усечённого результата, OF — знаковое переполнение. Переход JE проверяет ZF. Переход JB для беззнакового «меньше» проверяет CF, а JL для знакового «меньше» проверяет, различаются ли SF и OF. Учёт OF нужен, поскольку при переполнении знак усечённой разности не соответствует знаку математического результата.

Из каких действий складывается цикл

Пусть в строке четыре пикселя, а индекс первого равен нулю. Перед первой проверкой индекс получает значение 0. Проверка «индекс меньше 4» разрешает обработать пиксель. Затем индекс увеличивается на единицу, и программа снова проверяет условие. Последовательность допустимых индексов получается 0, 1, 2, 3.

После обработки индекса 3 увеличение даёт 4. Условие перестаёт выполняться, и программа переходит за цикл. Если заменить «меньше 4» на «меньше или равно 4», она попытается обработать пятый элемент. Ошибка возникает в условии, хотя сами команды чтения и записи могут быть исправны.

При трассировке записывайте индекс перед сравнением и адрес, выбранный после него. Такая запись позволяет проверить сразу два свойства: каждый допустимый элемент обрабатывается и выполнение заканчивается до обращения за границу.

Цикл как повторение переходов

Цикл является повторным выполнением участка программы с проверкой условия продолжения. Его удобно разбирать через начальное состояние, тело, изменение управляющей переменной и проверку. Пусть требуется сложить числа от 1 до 4. Начальное значение суммы равно нулю, счётчик равен единице. После первого шага сумма становится 1, после второго — 3, затем 6 и 10. После увеличения счётчика до 5 условие продолжения перестаёт выполняться.

Такой разбор позволяет обнаружить ошибку границы. Условие «счётчик меньше 4» выполнит только три сложения, тогда как «не больше 4» включит четвёрку. Для массива из четырёх элементов с нумерацией от нуля допустимы индексы 0, 1, 2 и 3. Поэтому типичное условие обхода имеет вид «индекс меньше длины». Наличие элемента с номером, равным длине, из этого не следует. На машинном уровне выход за границу может обратиться к существующей памяти, поэтому отсутствие немедленной аварии ещё не подтверждает правильность цикла.

Проверка перед телом допускает ноль повторений, если начальное условие ложно. Проверка после тела обеспечивает хотя бы одно выполнение. Различие существенно, например, при обработке пустого массива или отсутствующего входного блока. Перенос проверки без учёта этого случая изменяет поведение программы, даже если на обычных непустых данных результаты совпадают.

Цикл с условием i < 3, начальным i = 0 и прибавлением единицы обработает элементы с индексами 0, 1 и 2. Когда i станет равно 3, переход должен вывести исполнение из цикла до чтения элемента. Замена условия на i ≤ 3 разрешит ещё один проход. Для массива из трёх элементов этот проход обратится за его границы.

Диаграмма Харрисов показывает момент, когда условный переход меняет направление исполнения. Пока условие вычислялось, выборка успела получить команды, следующие за переходом в памяти. Если переход выполнен, эти команды удаляются из конвейера. Выборка продолжается с целевого адреса.

Как процессор возвращается из функции

Обработку одного пикселя можно вынести в функцию. Редактор вызывает её из разных мест, например при работе с основным изображением и с его уменьшенной копией. Чтобы продолжить работу в правильном месте, во время вызова нужно сохранить адрес команды, которая следует за вызовом.

В x86-64 команда call записывает адрес возврата в стек и передаёт управление функции. Стек — область памяти, из которой последнее помещённое значение извлекается первым. Адрес текущей вершины стека хранит регистр RSP. Команда ret получает сохранённый адрес с вершины и продолжает исполнение по нему.

Если вызванная функция вызывает ещё одну, второй адрес возврата попадает в стек поверх первого. Сначала завершается внутренний вызов, затем внешний. Этот порядок и позволяет пользоваться одной функцией из разных мест без отдельной копии её кода.

Вызов функции и соглашение о вызовах

Вызов функции должен обеспечить не только переход к её первой команде, но и возвращение в место продолжения. Адрес возврата хранит информацию о том, куда необходимо передать управление после завершения вызова. Стек удобно использовать для вложенных вызовов, поскольку последняя вызванная функция должна завершиться первой. Это соответствует дисциплине LIFO — последним поступил, первым извлечён.

Соглашение о вызовах определяет, где находятся аргументы и результат, какие регистры функция обязана сохранять и как поддерживается выравнивание стека. Если функция изменяет регистр, значение которого должна сохранить, она временно размещает старое значение в предусмотренном месте и восстанавливает его перед возвратом. Не все локальные переменные обязательно размещаются в стеке: компилятор может держать их в регистрах или вообще устранить. Поэтому стековый кадр является способом организации данных вызова, а не обязательной точной копией всех переменных исходного текста.

При рекурсии каждая незавершённая активация функции нуждается в собственном состоянии. Вызов для меньшего аргумента не должен уничтожить данные, необходимые вызывающей активации после возврата. Обычно часть такого состояния находится в стеке. Число одновременно незавершённых вызовов ограничивается ресурсами, поэтому бесконечная или слишком глубокая рекурсия может исчерпать стек.

В x86-64 команда CALL сохраняет адрес возврата в стеке и меняет адрес продолжения на начало функции. RET берёт адрес возврата со стека. Если функция выделила место под локальные данные или сохранила регистры, перед возвратом нужно восстановить указатель стека. Иначе RET прочитает значение, которое не было адресом возврата. Резервирование места для локальных данных и сохранение регистров составляют входную часть функции, обратные действия выполняются перед выходом.

Соглашение о вызовах определяет, где передавать аргументы и результат, какие регистры может менять вызываемая функция и как выравнивать стек. Регистры, которые разрешено менять при вызове, вызывающая сторона сохраняет, если их прежние значения ещё понадобятся. Регистры, закреплённые за вызывающей стороной, обязана восстановить функция, если она ими воспользовалась. Эти правила позволяют связывать части программы, скомпилированные отдельно.

Пусть функция A вызывает B, а B вызывает C. Для вызова B сохраняется адрес продолжения A, затем для C — адрес продолжения B. После завершения C управление возвращается в B, после завершения B — в A. Обратный порядок соответствует стеку. Если C повредит служебные данные своего вызова, ошибка может проявиться лишь при возврате. Поэтому место проявления сбоя не всегда совпадает с командой, которая первоначально записала недопустимые данные.

Когда адрес ещё существует, а объект уже недоступен

Функция может временно хранить в стеке локальные данные. На время работы они принадлежат её вызову. После возврата этот участок стека может использовать следующая функция. Даже если по прежнему адресу ещё видны старые числа, программа уже не вправе обращаться к завершившемуся объекту.

Граница объекта и время его существования проверяются независимо. Для четырёхэлементного массива индекс 4 выходит за пределы даже во время работы функции. А индекс 0 перестаёт быть допустимым после завершения функции, если речь о её локальном массиве, срок жизни которого истёк.

На практике поэтому спрашивают не только «как вычислен адрес», но и «к какому объекту он относится». Случайно полученное ожидаемое значение в одном запуске ещё не подтверждает правильность обращения.

Локальные данные и границы объектов

Объект программы имеет размер и время существования. Обращение к байтам за пределами объекта нарушает установленные границы, даже если эти байты принадлежат той же странице памяти. Например, массив из восьми элементов по четыре байта занимает 32 байта. При начале в условном адресе 2000 последний элемент начинается в 2028 и занимает байты до 2031 включительно. Запись по адресу 2032 уже не относится к этому массиву.

В стеке соседние данные могут включать сохранённые регистры и служебную информацию вызова. Ошибочная запись способна повредить их и проявиться позднее, при возврате или использовании другого значения. Современные средства защиты уменьшают риск и помогают обнаружить нарушения, но не отменяют необходимости соблюдать границы. В управляемых языках часть проверок выполняется автоматически, в низкоуровневом коде ответственность часто лежит на программисте. Архитектурная защита страниц и проверка границ отдельного массива решают разные задачи.

Время существования объекта также ограничивает допустимый доступ. Адрес локальных данных завершившегося вызова не становится надёжным способом сохранить их. Соответствующая область может быть занята следующим вызовом. Ошибка способна временно оставаться незаметной, пока байты не перезаписаны. Поэтому правильность указателя определяется не только его численным значением, но и существованием доступного объекта.

Как программа возвращается из вложенных вызовов

Когда одна функция вызывает другую, процессору нужно запомнить, с какого места продолжить работу после её завершения. Это место называется адресом возврата. В примере main вызывает average для трёх чисел, а average вызывает sum. Если сохранить только последнее место возврата, после завершения average будет потерян путь обратно в main.

Куда возвращается функция после вызова

На каждом шаге подсвечено действие в коде. Справа показаны места возврата, сохранённые для этих двух вызовов.

int sum(const int a[3]) {
    return a[0] + a[1] + a[2];
}
 
double average(const int a[3]) {
    int total = sum(a);
    return total / 3.0;
}
 
int main(void) {
    const int a[3] = {4, 8, 12};
    double result = average(a);
    return 0;
}

На x86-64 команда call кладёт восьмибайтовый адрес возврата в стек. Регистр RSP указывает на вершину стека. Команда ret берёт адрес с вершины и продолжает выполнение по нему. Поэтому сначала sum возвращает управление в average, а затем average возвращает его в main.

Этот порядок можно увидеть в отладчике. Если остановить программу внутри sum, в списке вызовов будут видны sum, затем average и main. По этому списку можно выяснить, из какой функции пришёл вызов.
