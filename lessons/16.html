От прошивки к ядру операционной системы

При включении прошивка инициализирует оборудование. Затем она выбирает загрузочную запись и запускает соответствующую программу EFI. В современной системе с UEFI выбор обычно осуществляется через загрузочную запись. Для диагностики важно понимать, на каком этапе компьютер остановился.

Чтобы запустить систему, прошивке нужно обнаружить накопитель, найти раздел EFI и открыть файл загрузчика. Прошивка может видеть диск, а нужная загрузочная программа отсутствовать. Ниже эти понятия применяются к современному меню UEFI и системному разделу EFI.

Начальная инициализация и POST

При запуске платформа подготавливает процессор, память и необходимые устройства. POST — начальные проверки, которые помогают обнаружить часть проблем до загрузки ОС. На разных платах результат обозначается индикаторами, звуковыми сигналами или кодами. Значение кода узнают по руководству именно этой модели; одинаковый цвет индикатора не имеет обязательного общего смысла для всех плат.

Инициализация памяти может включать обучение её параметров. После замены модулей или изменения настроек запуск иногда длится дольше обычного. Прерывать каждый такой запуск сразу после включения ошибочно, но бесконечно ждать без сверки с документацией тоже нельзя. Проверки POST не заменяют тест памяти и нагрузку после запуска: они подтверждают лишь определённый этап подготовки. Если изображение ещё не появилось, неисправность ОС нельзя считать установленной, поскольку управление могло до неё не дойти.

Как UEFI выбирает загрузочную программу

Загрузочная запись содержит сведения о том, какой файл и на каком устройстве нужно запустить. Менеджер загрузки прошивки перебирает записи в установленном порядке. Постоянный порядок загрузки и разовое меню выбора — разные средства: для учебной установки обычно удобно один раз выбрать проверенный носитель, не меняя надолго все приоритеты.

Наличие SSD в перечне устройств не означает, что на нём есть корректная загрузочная программа. Аналогично запись с названием ОС может сохраниться, хотя файл был удалён. Поэтому проверяют отдельно обнаружение накопителя, доступность нужного раздела и корректность записи. Современная загрузка UEFI использует исполняемые файлы EFI; старый совместимый режим не следует включать без необходимости. В смешанной конфигурации установщик и установленная ОС могут запускаться разными способами, что создаёт путаницу при поиске загрузчика.

Прошивка хранит загрузочные записи и их порядок в энергонезависимых переменных. Запись содержит путь к устройству и приложению EFI. В меню обычно видны названия записей, а не полный путь. Если накопитель перенесли или загрузочный файл переместили, запись может остаться в меню и стать нерабочей. И наоборот, файл на системном разделе EFI может существовать, хотя подходящей записи в меню уже нет. Эти два состояния требуют разных проверок.

Для установки и восстановления полезен разовый выбор загрузки. Он позволяет запустить установочный носитель и сохранить обычный порядок для следующих включений. После первого запуска установленной системы проверяют, что компьютер действительно загрузился с её записи. Повторное открытие установщика после перезагрузки может означать, что устройство с установщиком осталось первым в порядке загрузки.

В меню ASUS UEFI поле Boot Option #1 задаёт первый вариант при обычном запуске. Пункт Boot Override позволяет выбрать другой вариант для текущего запуска.

Где на накопителе лежит загрузчик

Накопитель предоставляет место для данных, но операционная система организует это место по частям. Раздел — выделенная область накопителя. Таблица разделов описывает, где начинаются и заканчиваются эти области. GPT — один из используемых форматов такой таблицы. Внутри раздела файловая система определяет, как файлы получают имена и где размещается их содержимое.

Для обычной загрузки с локального диска по UEFI предусматривают системный раздел EFI. На нём в доступной прошивке файловой системе хранятся файлы загрузочных программ. Загрузочная запись может указать прошивке устройство и путь к нужному EFI-файлу. Таким образом, таблица разделов помогает найти область, файловая система — найти файл, а запись загрузки — выбрать файл для запуска.

Если в меню сохранилось имя системы, но нужный файл удалён, выбор записи не запустит ОС. Если файл на месте, но запись потеряна, следует проверить, как прошивка находит этот файл. Обе ситуации возможны при исправном накопителе и требуют проверки разных вещей.

В «Управлении дисками» Windows системный раздел EFI отмечен отдельно от тома с Windows. Обычно у него нет буквы. При диагностике проверьте, на каком физическом диске расположен раздел EFI.

Что делает загрузчик и когда начинает работать ядро

Загрузчик — программа, которая получает управление от прошивки и подготавливает запуск ОС. Он находит нужные компоненты, размещает их в памяти и передаёт параметры запуска. Конкретная последовательность зависит от системы; в некоторых случаях цепочка включает несколько программ. После передачи управления ядро настраивает основные механизмы ОС и загружает необходимые драйверы.

Драйвер связывает программную модель устройства с его возможностями. Если ядро не может обратиться к системному накопителю через нужный контроллер, загрузка остановится, даже когда прошивка видела этот накопитель. Затем запускаются службы, отвечающие за сеть, вход пользователя и другие функции. Иллюстрация архитектуры UNIX/Linux показывает разделение приложений, ядра и оборудования после запуска. Она помогает увидеть цель загрузки, но не изображает все внутренние стадии конкретного установщика Windows или Linux.

Secure Boot и доверие к загружаемому коду

Secure Boot позволяет прошивке проверять загружаемые компоненты по настроенным доверенным ключам и спискам разрешений или запретов. Цель — ограничить запуск неподтверждённого кода в начале цепочки. Цифровая подпись связывает компонент с доверенным издателем и позволяет обнаружить его изменение; наличие подписи не доказывает отсутствие любых ошибок в программе.

Secure Boot не шифрует пользовательские файлы и не заменяет резервную копию. Он также не требует, чтобы любое приложение пользователя проверяла именно прошивка. Если проверенный установочный носитель не загружается, сначала выясняют, какой этап и компонент отклонён, правильно ли подготовлен носитель и поддерживается ли выбранный режим. Отключение защиты ради обхода непонятного сообщения не является универсальным первым шагом. Подробную связь загрузки, TPM и аппаратной защиты рассмотрим в следующей лекции.

Подготовка учебной установки

До установки проверяют поддержку ОС процессором и устройствами, достаточность памяти и места на диске, наличие драйверов сети и контроллера хранения. Образ получают у разработчика или официального распространителя. Если опубликована контрольная сумма или подпись, проверяют её установленным способом. Сумма подтверждает совпадение файла с эталоном, поэтому источник самого эталона также должен быть доверенным.

Для практики используют отдельный учебный накопитель или виртуальную машину. Сначала записывают, какие данные требуется сохранить, затем определяют целевой диск по модели и объёму. Номер диска сам по себе недостаточно надёжен: при изменении подключения он может поменяться. Удаление разделов — отдельное осознанное действие, а не обязательный способ исправить любую загрузку. Перед изменением разметки должна быть проверенная резервная копия нужных данных.

Установка драйверов и проверка готовой системы

После первого запуска сверяют состав устройств и состояние драйверов. Драйвер получают через поддерживаемый механизм ОС либо у изготовителя конкретного устройства. Универсальная программа, обещающая заменить всё сразу, затрудняет проверку происхождения и откат. Версию обновления фиксируют, особенно если оно меняет контроллер хранения, сеть или графическую подсистему.

Проверяют загрузку после перезапуска, сеть, звук, изображение, сон и пробуждение там, где они требуются. Обновления устанавливают с учётом документации и возможности восстановления. Изменение режима контроллера хранения в прошивке после установки может лишить ОС доступа к диску без предварительной подготовки. Поэтому настройку не меняют как случайный эксперимент. Итоговая конфигурация включает не только список компонентов, но и режим загрузки, версию прошивки, схему разделов и существенные параметры драйверов.

Как файловая система связывает имя и блоки

Загрузочные программы и ядро хранятся как данные, но поиск по имени требует структуры файловой системы. Каталог связывает имя с записью об объекте, а метаданные содержат сведения о размере, расположении и свойствах. Содержимое файла может занимать несколько раздельных участков. Поэтому соседние по имени файлы не обязаны лежать рядом на накопителе, а удаление имени не означает немедленного физического стирания всех байтов.

При открытии файла ОС проходит каталоги, проверяет права и находит нужные блоки. Часть сведений уже может быть в кэше. Запись сначала способна изменить буферы памяти, а затем попасть на устройство хранения. Поэтому исчезновение окна приложения не доказывает, что отключение питания уже безопасно в любой ситуации. Корректное завершение и предусмотренные средства сброса данных согласуют изменения. В начале курса достаточно понимать эти уровни; конкретные структуры NTFS и ext4 изучают подробнее в дисциплине об операционных системах, не смешивая их с физическим устройством SSD.

Таненбаум и Бос показывают каталог как структуру, которая связывает имя файла с его описанием. Когда прошивка открывает загрузочный файл, сначала нужно найти подходящий раздел, затем прочитать каталог и найти запись нужного имени. Поэтому наличие раздела и наличие файла проверяют отдельно.

Восстановление загрузки и обновление прошивки

Среда восстановления ОС помогает проверить системный раздел, восстановить загрузочные файлы или отменить часть изменений. Это программная среда с собственными требованиями к архитектуре, режиму запуска и драйверам. Перед действием определяют целевую установку, поскольку на компьютере может быть несколько ОС. Восстановление загрузчика не равнозначно удалению всех разделов или переустановке приложений.

Обновление прошивки платы — другое действие: оно меняет встроенное программное обеспечение платформы. Файл должен предназначаться для точной модели и её аппаратной ревизии. Сначала читают примечания к версии и порядок обновления, проверяют устойчивое питание и доступность ключей восстановления зашифрованных дисков. После обновления сверяют существенные настройки, поскольку часть могла измениться или сброситься. Нельзя считать любое более новое имя файла гарантией совместимости. В учебном отчёте явно разделяют «восстановили запись загрузчика», «обновили драйвер» и «обновили прошивку»: эти операции относятся к разным слоям и имеют разные способы проверки.

Как выбрать проверку по последнему успешному этапу

Рассмотрим три результата на учебном ПК. Если после включения не завершается начальная проверка, начните с того узла, который отмечен диагностикой платы, и сверяйте значения по её руководству. Исправлять загрузчик в этот момент преждевременно: прошивка могла ещё не начать поиск загрузочных программ.

Если прошивка видит SSD, но в меню нет ожидаемой загрузочной записи, выясните, установлен ли на диск загрузчик и в каком режиме устанавливалась система. Для чистого SSD такое состояние нормально. Если загрузчик запускается, но ядро ОС не видит системный диск, круг проверок меняется: теперь важны параметры контроллера, поддержка накопителя и драйверы.

Записывайте конкретный признак и следующую проверку. Формулировка «прошивка видит SSD, запись ОС отсутствует» даёт больше информации, чем «ПК не грузится». Практика в следующем разделе показывает, где именно искать эти сведения в меню UEFI.

UEFI показывает исправно подключённый SSD, но сообщает об отсутствии загрузочного устройства. Это подтверждает обнаружение накопителя, но не наличие рабочего загрузчика. Проверяем, в каком режиме установленная ОС должна запускаться, существует ли нужная загрузочная запись и доступен ли раздел EFI. Если запись потеряна, восстановление выполняют средствами соответствующей ОС. Форматировать SSD только по этому сообщению оснований нет.

Базовые настройки UEFI

В меню прошивки можно проверить, какие компоненты определились до запуска операционной системы, выбрать устройство для загрузки и посмотреть работу охлаждения. Традиционный BIOS (Basic Input/Output System) — более ранний тип системной прошивки ПК. UEFI определяет современный интерфейс между прошивкой и загрузчиком. Производители по-прежнему употребляют слово BIOS в названии меню, даже когда плата работает с UEFI. Названия пунктов и клавиши зависят от модели. Ниже в качестве примера используется меню ASUS UEFI EZ Mode.

1. Вход и сведения о системе. Во время начального запуска нажмите клавишу, указанную на экране или в руководстве платы. На многих платах ASUS это Del или F2. На странице Main или в обзорном экране EZ Mode запишите модель процессора, объём обнаруженной оперативной памяти и версию прошивки. Найдите SSD в сведениях о накопителях. Если устройство там есть, но отсутствует в списке загрузки, отдельно проверьте наличие загрузочной записи.

2. Температура и вентиляторы. Откройте Monitor, Hardware Monitor или Q-Fan Control. Сверьте температуру CPU и скорость вентилятора процессора, которая указывается в оборотах в минуту (RPM). При воздушном охлаждении с вентилятором на CPU_FAN проверьте, что плата видит его обороты. Если обороты не отображаются, сначала выясните, куда подключён вентилятор. В Q-Fan можно выбрать штатный профиль, например Standard. Кривая вентилятора связывает показание датчика температуры с управляющим сигналом вентилятора. При настройке сравнивают показания температуры и оборотов до и после изменения.

3. Выбор загрузки. Для однократного запуска с учебной флешки откройте Boot Menu и выберите её загрузочную запись. На рассматриваемом экране ASUS меню вызывается клавишей F8. Для постоянного изменения используйте Boot Priority или Boot Option Priorities. Если система уже установлена, запись может называться Windows Boot Manager или именем другого загрузчика. После работы проверьте, что обычная система по-прежнему запускается с нужной записи.

4. Сохранение и выход. Если вы только осматривали настройки, выберите Discard Changes and Exit или эквивалентный пункт. Чтобы применить изменения, выберите Save & Exit и просмотрите список изменений, если меню его показывает. В примере ASUS клавиша F10 открывает сохранение с выходом. При учебной проверке меняйте по одному параметру и записывайте результат следующего запуска.

5. Возврат к значениям по умолчанию. Сначала запишите важные настройки загрузки, контроллера накопителей, памяти и охлаждения. Затем при необходимости выберите Load Optimized Defaults или Restore Defaults, проверьте параметры и только после этого подтвердите сохранение. Если изменится режим контроллера накопителей, установленная ОС может перестать загружаться. На ПК с шифрованием диска заранее проверьте доступ к ключу восстановления, если планируете менять настройки безопасности. Первый осмотр меню выполните без сохранения изменений.

В типичной прошивке пункт Boot Override запускает выбранное устройство один раз, а Boot Option Priorities меняет очередность следующих запусков. Для старта установщика с флешки удобно воспользоваться первым вариантом. При переносе SSD на другую плату загрузочный файл может остаться на диске, а запись о нём в памяти прошивки новой платы может потребоваться создать заново.

В учебном ПК нужно один раз запустить установщик с USB, сохранив обычный запуск с внутреннего SSD. Проверьте, что обе записи видны, выберите флешку через разовое меню, а затем перезагрузите компьютер без флешки. Ожидаемый результат — обычная ОС снова запускается без ручного выбора.
